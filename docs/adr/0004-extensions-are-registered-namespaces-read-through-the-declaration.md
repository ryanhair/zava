
- Amended (options at the declaration root). An extension's options sit at the root of the declaration under the extension's name; there is no `extensions` block, in a `resource` declaration or in a value type's. Measured on the prototype branch `prototype/flat-extension-options` (Zig 0.17.1): the whole options type is built with `@Struct` from the kernel's hand-written fields plus one optional field per extension; a misspelled kernel option, a misspelled extension name and a missing required option are compiler errors on the exact token, and the type keeps a readable name (`zava.Options(Author)`).
- Kernel names and extension names share one namespace. An extension may not have the name of a kernel option at the root of a `resource` declaration, of a kernel option of a value type's declaration, or of a kernel step kind (a step entry is keyed the same way, ADR 0014). A clash is a compile error at the domain root that names the extension. Two extensions with one name are the same error. There is no renaming at registration: the name is the extension's own, and its author resolves a clash.
- The kernel adding a name later breaks a build that registers an extension of that name, so a new kernel option or step kind is a breaking change of the kernel and is announced as one. Extension authors are advised to name an extension after the thing it is (`postgres`, `http_api`, `state_machine`), not after a general modelling word the kernel might want.
- Nothing in the declaration marks a field as the kernel's or an extension's. Documentation writes the kernel's options first and extension entries after them; nothing enforces it.
- Editor cost on ZLS 0.17.0, inferred from the measurement that it resolves every `@Struct` type to an unknown type and not measured again: the kernel's top-level option names lose completion, hover and go-to-definition, and so does everything typed through the root. What still gets them: an entry hoisted into a constant of its public type (ADR 0001), and an extension entry written with the extension's named type, which now has better editor support than the kernel's own options. Accepted, and it returns without a change here once the language server gets types from the compiler.
- An extension's per-attribute options stay a block of its own inside its options; merging them into the kernel's per-attribute block stays rejected.
